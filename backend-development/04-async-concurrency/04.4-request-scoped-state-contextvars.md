# 04.4 Request-Scoped State — contextvars

> **Prerequisites:** 04.1 (one thread, task per request) · 03.7 (RequestContextMiddleware, outermost) · 03.5 (explicit dependencies) · 03.6 (def endpoints on the threadpool) · modern-python 12.x (tasks — assumed)
> **What you'll learn:**
> - Say why `threading.local` — correct for a decade of thread-per-request servers — becomes a cross-request bleed the day the server goes async
> - Use `ContextVar` with its actual semantics: per-task copied contexts, snapshot-at-creation inheritance, tokens and reset
> - Know exactly where context travels for free (child tasks, `def` endpoints via anyio) and where it silently doesn't (raw executors)
> - Draw the line between ambient context (ids, tenant-for-telemetry) and business inputs — and keep the second out of contextvars
> - Wire the request-id-in-every-log-line machinery that 03.7 promised, and test that identity never bleeds
> **Level:** Intermediate

> ⚡ **Wednesday 28 October, 14:15** — a customer's SOC2 reviewer finds other tenants' operations inside their audit-log export. No authorisation check failed anywhere. The cause: one word — `threading` — in a module older than the API.

## Concept

### Plain-English Explanation

Some facts about a request are needed *everywhere* and belong in *no function signature*: the request id that must appear on every log line (03.7's promise), the tenant stamped on audit events, the trace id (15.x). Threading them through every call as parameters would put telemetry plumbing in every signature in the codebase. Every server framework therefore grows a notion of **ambient, request-scoped state** — "the current request's X" — readable from anywhere, valid only inside that request.

For the thread-per-request era the tool was `threading.local`: one thread served one request, so per-thread storage *was* per-request storage. 04.1 dismantled the premise: one thread now serves every request, interleaved at awaits. A thread-local on that thread is not request-scoped — it is a **global with a rotating value**, and whichever request wrote last owns it. `contextvars` is the standard library's replacement: state scoped to the *logical flow of control* — the task — rather than to the thread that happens to run it.

### Technical Explanation

**The semantics that matter.** A `ContextVar` is read and written against the **current `Context`** — an immutable-ish mapping the runtime carries alongside execution. The rules, each one captured below: every task created gets a **copy** of its creator's context at creation time (`asyncio.create_task` → `copy_context()`); uvicorn runs **each request as a fresh task**, so requests start from a clean copy and nothing a request sets survives into the next one; `var.set()` returns a **Token** so the previous value can be restored with `var.reset(token)` — hygiene inside shared machinery like middleware.

**The bleed, measured.** Forty concurrent "requests", each setting its identity then hitting one `await`:

```text
threading.local wrong after one await: 39/40
ContextVar      wrong after one await: 0/40
```

39 of 40 requests woke up believing they were someone else. And it isn't only bleed *between* live requests — the server capture below shows a request that sets nothing reading a **stale identity from a request long finished**, because thread state outlives requests:

```text
handled rid=r_002 | ctxvar=r_002 | thread_local=r_005     ← every ctxvar right,
handled rid=r_001 | ctxvar=r_001 | thread_local=r_005       every thread_local =
handled rid=r_000 | ctxvar=r_000 | thread_local=r_005       whoever wrote LAST
...
next request on the same connection, sets nothing:
/v1/peek sees: {'ctxvar': '-', 'thread_local': 'r_AAA'}   ← stale leak vs clean copy
```

**Inheritance is a snapshot, not a subscription.** A task created mid-request captures the context *as it is at creation*:

```text
parent set t_44f1, spawned child, then set t_9999
child sees: t_44f1   parent now: t_9999
```

Two consequences. The good one: a task spawned while handling tenant `t_44f1`'s request carries that identity into its own logging forever, however long it runs. ⚠️ The subtle one: that snapshot **pins the captured values alive** for the task's lifetime — a long-lived task launched from a request (03.10's temptation) drags request-era context with it, and its log lines claim a request that ended hours ago.

**Where context does not travel.** Threads, unless someone carries it:

```text
loop.run_in_executor(...)     sees: '-'          ← raw executor: context LOST
anyio.to_thread.run_sync(...) sees: 't_44f1'     ← what def endpoints use (03.6)
```

Starlette runs `def` endpoints through anyio, which copies the context into the worker thread — so request ids appear in `def`-endpoint logs *for free*, which feels like magic until a raw `loop.run_in_executor` call elsewhere loses them and the logs go anonymous. The fix for the raw path is `copy_context().run(fn)` — explicit carriage.

### Mental Model

> A `ContextVar` is a **per-flow environment variable**: every task is born with a copy of its parent's environment, writes stay in your copy, and the copy dies with the flow. A thread-local in an async server is the opposite — one whiteboard bolted to the only thread, overwritten by whoever passed most recently, readable by whoever comes next. If a value describes *who this flow is* (ids, tenant-for-telemetry), it belongs in the environment; if a function's *behaviour* depends on it, it belongs in the signature.

## How It Works

The bleed and the isolation, on one timeline — two requests on 04.1's single thread:

```text
one thread, interleaved:                 thread.local        ContextVar
t=0  req-A middleware: identity=A           [A]           ctxA{tenant=A}
t=1  req-A awaits the DB          ──────────────────────────────────────
t=2  req-B middleware: identity=B           [B] ⚠️         ctxB{tenant=B}   (fresh copy)
t=3  req-B awaits the tax API     ──────────────────────────────────────
t=4  req-A resumes; audit reads:            [B] WRONG      ctxA → A  ✓
t=5  req-A ends; conn stays open            [B] persists   ctxA destroyed
t=6  req-C (same conn, reads only):         [B] STALE      ctxC → default ✓
```

And where the context flows from a request task, with the two boundary rules:

```text
request task ctx ──▶ create_task(...)         copy at creation   (snapshot: keeps identity,
                 │                                                pins values alive)
                 ├─▶ TaskGroup children        copies             (03.8's groups: same rule)
                 ├─▶ anyio.to_thread / def     copied into thread (Starlette carries it)
                 ├─▶ loop.run_in_executor      ✗ NOT carried      (copy_context().run to fix)
                 └─▶ BackgroundTasks           copied             (attribution survives the
                                                                   response — 03.10)
```

One design boundary keeps this power safe. Contextvars are for **ambient** concerns — values telemetry and audit want everywhere and business logic wants nowhere. The moment a service function's *result* depends on a contextvar, that function has a hidden parameter: it can't be called correctly from a worker (10.x — no request context exists there), tests must remember to seed invisible state, and 03.5's whole explicit-dependency design is quietly bypassed. Ledgerly's rule: tenant *for authorisation and queries* arrives as a `Depends` parameter (03.5, unchanged); tenant *for log lines and audit stamps* rides the contextvar. Same fact, two channels, on purpose — the signature one is checked by the type system, the ambient one merely enriches telemetry.

## Code Example

The machinery 03.7 registered as its outermost middleware, mechanism finally shown — set, stamp, and reset in `finally`:

```python
# ledgerly/middleware/request_context.py (03.7's outermost; 15.2 grows it)
request_id_var: ContextVar[str] = ContextVar("request_id", default="-")
tenant_var: ContextVar[str] = ContextVar("tenant", default="-")

class RequestContextMiddleware:
    def __init__(self, app: ASGIApp) -> None:
        self.app = app

    async def __call__(self, scope, receive, send) -> None:
        if scope["type"] != "http":
            return await self.app(scope, receive, send)
        rid = Headers(scope=scope).get("x-request-id") or f"req_{uuid7().hex[:12]}"
        token = request_id_var.set(rid)
        try:
            await self.app(scope, receive, send)
        finally:
            request_id_var.reset(token)    # hygiene: this CONTEXT outlives the
                                           # request only inside shared machinery,
                                           # but never rely on task teardown for you
```

The reset deserves its honest footnote: because uvicorn gives each request a fresh task-context, a leaked set dies with the task anyway (the `/v1/peek` capture: ctxvar came back clean even without reset). The `finally` is still right — middleware also runs under TestClient, scripts, and nested lifetimes where the context *is* shared — but you should know which guarantee comes from your discipline and which from the runtime. The consumer side is one logging filter, and every log line in the process gains the id:

```python
# ledgerly/observability/logging.py
class ContextFilter(logging.Filter):
    """Stamps ambient identity onto every record — handlers format it once,
    and no call site ever passes request_id again (03.7's promise, kept)."""
    def filter(self, record: logging.LogRecord) -> bool:
        record.request_id = request_id_var.get()
        record.tenant = tenant_var.get()
        return True

# formatter: "%(asctime)s %(levelname)s %(request_id)s %(tenant)s %(message)s"
```

And the audit emitter — the incident's crime scene — after the fix, with the guard that keeps ambient state honest:

```python
# ledgerly/audit/emit.py (16.13's consumer)
def emit_audit_event(action: str, resource: str) -> None:
    tenant = tenant_var.get()
    if tenant == "-":                     # no ambient identity: refuse loudly.
        raise RuntimeError(               # a worker (10.x) must pass identity
            "audit event outside request context — pass tenant explicitly")
    AUDIT_LOG.info("audit", extra={"action": action, "resource": resource})
```

> **Version note** — captured on Python 3.14: `anyio.to_thread.run_sync` (Starlette's `def`-endpoint path) copies the context into the worker thread; bare `loop.run_in_executor` does not — both shown in `_lab/lab_04_04_contextvars.py`. asyncio has carried contexts through `create_task` since 3.7, so none of this is version-fragile; the *libraries'* propagation choices are where behaviour differs.

## Design Patterns / Tradeoffs

### Where should "the current X" live?

- **Explicit parameters / `Depends` (03.5):** visible in signatures, type-checked, trivially testable, works in workers. *Cost:* every layer signs for it. *Use for:* anything behaviour depends on — tenant for queries, user for authorisation, feature flags. The default; the other options must justify themselves against it.
- **`request.state` (Starlette):** scoped to the request object; good for request-lifecycle plumbing that handlers and middleware share (03.9's yielded state pattern). *Cost:* needs the `Request` in hand — so it *is* a parameter, just an untyped grab-bag one. *Use for:* framework-adjacent plumbing; not deep call stacks.
- **`ContextVar`:** ambient, survives into child tasks and `def` threads, invisible to signatures. *Cost:* that same invisibility — hidden coupling, silent `default` reads outside requests, snapshot lifetimes. *Use for:* telemetry identity (request id, trace id, tenant-for-logs) — values whose absence degrades observability, never correctness.
- **`threading.local`:** correct only where thread == flow — inside a single `def` endpoint's borrowed thread, or sync-only codebases. *Never* as request scope in an async server; the lab's 39/40 is the whole argument.

**Recommendation:** parameters for behaviour, contextvars for telemetry, `request.state` for framework plumbing — and any PR moving a value *down* that list carries the burden of proof. Revisit at 15.2 (trace propagation) where the ambient channel earns its keep at scale.

## Production Scenario

**Ledgerly, Wednesday 28 October, 14:15.** An enterprise customer's SOC2 reviewer, working through their quarterly audit-log export (16.13's per-tenant export), files a P1: their file contains **operations belonging to other tenants** — action types, invoice ids, API-key prefixes of companies they can name from the id format. Not their data payloads — but other tenants' *activity*, attributed into their audit trail. Legal is cc'd by 14:40.

### Symptoms

- The export pipeline is correct: it faithfully returns every audit row stamped `tenant=t_44f1`. The rows themselves are mislabelled — the stamping was wrong *at write time*.
- Sampling the audit table: ~7% of rows in the last month carry a tenant that doesn't match the API key on the same row (a cross-check nobody had run — the columns were assumed redundant).
- The mislabel rate is load-shaped: near zero at night, peaking at the busiest hours — and it starts, precisely, at the deploy that moved Ledgerly from the old sync stack to FastAPI (module 03's migration).

### Diagnosis

1. **Alert → the data itself.** No server-side alert ever fired — mislabelled writes are 03.13's class of failure (wrong data, zero errors), and the detector is the customer plus the row-level invariant `audit.tenant == tenant_of(audit.api_key)`, computable in one query. Run it: 7%, load-correlated, starting at the async migration.
2. **Load-shaped + async migration** is the fingerprint of an interleaving bug: the more concurrent requests, the more often *something shared* is overwritten between a request's write and its read.
3. **Read the writer.** `emit_audit_event` pulls tenant from `audit_context.py` — a module dated four years back, ported whole from the Flask codebase: `_ctx = threading.local()`. Under Flask (thread per request) this was correct for years, which is exactly why nobody flagged it in the migration review: the module didn't change, the *server model under it* did.
4. **Confirm the mechanism** with the lab's experiment shape: set identity, one await (the audit emitter awaits an INSERT before reading the var for the log line), read — 39/40 wrong under interleaving. In production the window between middleware-set and audit-read spans the whole handler: every await inside is a chance for another request's middleware to overwrite the thread-local. 7% is just the collision probability at Ledgerly's concurrency.

### Root Cause

A Flask-era `threading.local` carried "current tenant" into the async server, where one thread serves all requests: any request that awaited between the middleware's write and the audit emitter's read could have its identity overwritten by whichever request ran in between, mislabelling ~7% of audit rows — a correctness failure with zero errors, surfacing only as wrong attributions in a compliance artefact.

### Fix

*Mitigation (day one):* the audit emitter switched to read tenant from the **request's explicit dependency** (03.5's resolved tenant, passed down one level) — parameters can't bleed; deployed by 17:00. Historical rows: re-labelled from the API-key column (the redundancy that made the cross-check possible), with the affected tenants notified per the incident policy (16.x).

*Permanent fix:* `audit_context.py` deleted; ambient identity rebuilt on `ContextVar` (the Code Example) for telemetry and log enrichment, while everything behaviour-bearing stays parameterised. The guard in `emit_audit_event` refuses to stamp the default value, so "no context" fails loudly instead of writing `-` or worse.

### Prevention

- **The row-level invariant becomes a nightly check**: `audit.tenant == tenant_of(audit.api_key)` — 03.13's lesson (only an invariant catches wrong-data failures) now applied to the audit trail itself.
- **The incident closes into a named CI test** — forced interleaving, distinct identities, exact attribution:

```python
# tests/context/test_identity_never_bleeds.py
async def test_concurrent_requests_keep_their_own_identity(client) -> None:
    """Two tenants' requests interleave at every await; every audit row and
    log record must carry the identity of ITS OWN request (28 Oct, 04.4)."""
    async with asyncio.TaskGroup() as tg:
        for tenant in ("t_aaa", "t_bbb") * 20:
            tg.create_task(client.get("/v1/invoices", headers=auth_for(tenant)))
    for row in captured_audit_rows():
        assert row.tenant == tenant_of(row.api_key), row      # zero tolerance
```

- The 04.2-style **import guard extends its blocklist**: `threading.local` in any request-path module is a finding — the pattern is banned where flows outnumber threads, and the test names the one legacy module that was exempt until deleted.

## Failure-First Checklist

| What if... | Answer |
|---|---|
| ...a thread-local sneaks into async request code? | Bleed under interleaving (measured 39/40) plus stale leakage into later requests. Banned by the import guard; caught by the interleave test. |
| ...someone forgets `reset(token)`? | Inside uvicorn's per-request tasks the leak dies with the task (captured: next request reads clean). In shared contexts — tests, scripts, nested middleware — it lingers: keep the `finally`. |
| ...a contextvar is read outside any request? | You get the `default` — silently. Anything that *stamps* data must refuse defaults loudly (the audit guard); telemetry may degrade gracefully. |
| ...a long-lived task is spawned from a request? | It snapshots and *pins* request-era context: wrong attribution forever, values kept alive. Long-lived work starts from lifespan (03.9) with its own identity, not from requests. |
| ...work hops to a thread? | `def` endpoints and `anyio.to_thread` carry the context (captured); raw `run_in_executor` loses it — wrap with `copy_context().run` or pass values explicitly. |
| ...work hops to a worker process (03.10, 10.x)? | No context crosses a process boundary, ever. Identity travels in the job payload, explicitly — which is why business logic must accept it as a parameter. |
| ...business logic starts reading a contextvar? | A hidden parameter: untestable without seeding, broken in workers, invisible in review. Move it to the signature; leave the var to telemetry. |
| ...the same fact lives in a parameter and a var? | Fine, by design — but only one is authoritative (the parameter). Add the invariant check if the duplicate gets persisted, as audit rows now do. |

## Common Pitfalls

**Porting `threading.local` across the sync→async boundary.** The module that "didn't change" met a server model that did — four years of correctness ended silently. *Instead:* ContextVar for ambient state; the import guard so the port can't recur.

**Contextvars as a parameter-passing shortcut.** Ambient business inputs are hidden coupling: unseeded tests pass wrongly, workers break, signatures lie. *Instead:* behaviour through parameters (03.5); vars carry telemetry.

**Trusting defaults silently.** `var.get()` outside a request returns the default and nothing warns you — `tenant="-"` stamped into a compliance record is the quiet version of this incident. *Instead:* refuse defaults at every write-path consumer.

**Spawning long-lived tasks from request context.** The snapshot pins identity and memory to a request that ended. *Instead:* lifespan-born tasks (03.9); pass identity into jobs explicitly.

**Assuming context follows work everywhere.** It follows tasks and anyio threads, not raw executors, subprocesses, or queues. *Instead:* know the captured matrix; carry explicitly at every boundary it doesn't cross.

**Set without reset in shared machinery.** Safe-by-accident under uvicorn's fresh task contexts, wrong everywhere else. *Instead:* token + `finally` — discipline you own beats a guarantee you borrowed.

## How to Test This

- The interleave test above: concurrent requests with distinct identities, zero-tolerance assertion on every audit row and captured log record — this fails within seconds against a thread-local.
- The import guard extension: `threading.local` blocklisted in request-path modules (04.2's mechanism, one more entry).
- A boundary matrix test pinning the captured propagation rules: child task sees snapshot; `def` endpoint sees the request's id; raw executor sees the default — so a library upgrade changing propagation behaviour fails loudly.

## Interview Questions

1. *Explain.* Why is `threading.local` broken in an async server, having been correct for years in a threaded one? — Its scope is the thread; the async server multiplexes all requests onto one thread, turning per-request storage into a last-writer-wins global (measured: 39/40 misattributed after one await).
2. *Explain.* The three ContextVar rules that make it request-safe. — Tasks copy the context at creation (fresh per request, snapshot for children); writes stay in the copy; tokens allow scoped reset. Isolation comes from the copy, not from locking.
3. *Debug this.* ~7% of audit rows carry the wrong tenant, worse at peak load, started after an async migration; no errors anywhere. — Interleaving overwrite of shared mutable "current X" state (thread-local or module global) between set and read; find the ambient-state module the migration didn't touch; verify with a forced-interleave test and a row-level invariant.
4. *Design.* Request-id-on-every-log-line for a FastAPI service. — Outermost pure-ASGI middleware sets the var (token/reset in finally), a logging.Filter stamps every record, formatter renders it; child tasks and `def` endpoints inherit automatically; raw executor calls wrap in `copy_context().run`.
5. *Explain.* Where does a contextvar's value NOT follow the work, and what do you do at each boundary? — Raw executors (wrap or pass), processes and queues (explicit payload fields), and any long-lived task you *shouldn't* have spawned from a request (restructure).
6. *Design.* Draw the line: which of tenant-for-authorisation, trace-id, feature-flags, locale goes ambient? — Trace-id (and request-id): ambient. Tenant-for-authz and flags: parameters — behaviour depends on them. Locale: parameter if it changes results, ambient if it only decorates telemetry. The rule: correctness through signatures, observability through context.
7. *Explain.* What does snapshot inheritance imply for a task spawned per request that outlives the request? — It carries (and pins alive) the dead request's identity: misattributed logs and retained memory. Long-lived tasks belong to lifespan; request identity reaches jobs as data.

## Key Takeaways

- One thread serves every request (04.1), so thread-locals are last-writer-wins globals: 39/40 misattributions after a single await, plus stale leakage into requests that wrote nothing.
- `ContextVar` scopes state to the flow: each task a copied context, writes local to the copy, children snapshotting at creation — isolation by copying, no locks involved.
- Know the propagation matrix cold: child tasks ✓, `def` endpoints via anyio ✓, `BackgroundTasks` ✓, raw `run_in_executor` ✗, processes/queues ✗ — carry explicitly where it doesn't flow.
- Ambient state is for telemetry identity only; anything behaviour depends on goes through signatures (03.5). Same fact may ride both channels — the parameter is authoritative.
- Write-path consumers refuse default values loudly; only telemetry may degrade quietly.
- Token + `finally` reset is your discipline; uvicorn's fresh per-request contexts are the runtime's — know which guarantee you're standing on.
- Wrong-data failures alert nobody: the row-level invariant (`audit.tenant == tenant_of(api_key)`) and the forced-interleave test are the only detectors this class has (03.13's lesson, again).
